# Parity contract: Python app to Rust app

This is the definition of done for the Rust rewrite. The Rust app replaces the
Python app (the Python app is deleted at cut-over; nothing binds the two
together), so parity is measured from the outside: same input, compare output.

Rule for the whole port: a commit either moves behaviour to Rust unchanged, or
changes behaviour. Never both. Improvements noticed during the port go in the
follow-up list at the bottom.

## Unit of parity

One run: a media file and a set of options in, a transcript and its export
files out.

## Must match exactly

Checked by replaying `fixtures/*.json` (generated by
`python tools/parity/dump_fixtures.py`) in `cargo test`.

| Area | Python source | Fixture file | Cases |
|---|---|---|---|
| Number, percent, currency, ordinal formatting; filler removal | `src/itn.py`, `src/transcription/post_processing.py` | `text.json` | 18,665 (all text functions) |
| Repetition and hallucination filters, rolling prompt | `src/transcriber.py`, `src/text_postprocessor.py` | `text.json` | included above |
| Segment post-processing, speaker alignment and merging | `src/text_postprocessor.py`, `src/aligner.py` | `segments.json` | 40 |
| TXT, SRT, VTT, Markdown, JSON, CSV export; rename, search, replace, statistics | `src/exporter.py`, `src/aligner.py` | `transcript.json` | 44 |

The report for every differential run states the number of cases compared and
the number that differ. A bare "pass" is not a result.

## Must match within a tolerance

| What | Tolerance | How it is measured |
|---|---|---|
| Word error rate | Rust at most 1.0 percentage point worse than Python, same model size | `tools/benchmarks/benchmark_fleurs.py`, 150 FLEURS Turkish test clips |
| Segment start and end times | within 0.5 s for matching segments | same run |
| Long recordings with several speakers | no number; speaker count and a listening check | three Turkish YouTube videos with human-made captions |

Speech recognition is not bit-reproducible across engines, so text from the
recogniser itself is never compared exactly.

## Allowed differences

- The "created at" line in TXT, Markdown and JSON exports (fixtures use the
  fixed time 2026-01-02 03:04:05; the Rust code takes the clock as an input).
- Wording of progress and log messages.
- `is_repetition_loop` near its threshold: it depends on zlib's compressed
  size, which can differ by a few bytes between zlib implementations. The
  Rust port must match on every fixture case; if a case sits on the boundary
  and differs, record it here with the two ratios rather than tuning the
  threshold.

## Python-to-Rust traps the fixtures cross

- Turkish casing: `İ`, `I`, `ı`, `i` through `.lower()` and `.upper()`.
- Text sliced by character position (`prev[-150:]` in `build_rolling_prompt`)
  with non-ASCII characters at the cut.
- Empty string, whitespace-only string, empty segment list.
- Rounding of times (`round(x, 2)`) and millisecond carry in SRT/VTT
  timestamps (59.9996 s, 3599.9999 s).

## Deliberately not ported

| Python | Why |
|---|---|
| `src/diarizer.py` (pitch and mel clustering) | Replaced by an offline speaker-embedding model. Speaker labels are therefore not compared with Python. |
| Pyannote mode and the Hugging Face token setting | Never worked in a released build (`pyannote` is not a dependency). |
| `src/language_model.py` lexicon snapping | Removed from the pipeline in v1.1.6: with the 85-word built-in list it rewrote ordinary words ("Ben biz var" became "Bes bir ver"). |
| Built-in default hotword list | Removed in v1.1.6: it biased every transcript toward nursery words. |
| `src/updater.py`, `src/bootstrapper.py`, PyInstaller and Flet workarounds in `main.py` | Replaced by the Tauri updater and bundler. |
| `src/ui/` | The interface is redesigned, not ported. |
| `src/tts/`, `src/transcription/engine.py`, `src/ui_flet/` | Not used by the app. |
| Any accuracy step that does not lower WER in `docs/BENCHMARKS.md` | Measured, not assumed. |
